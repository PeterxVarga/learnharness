# R16.12.1 – Real upstream 0.4.1 lint blocker

Fedora owner execution on 2026-10-31 verified the 0.4.1 source snapshot and R15
portable assembly, then stopped at the first lint gate:

- `tredven/addons/components/gusek-gmpl-editor.tsx:74`:
  `Definition for rule 'react-hooks/exhaustive-deps' was not found`
- `tredven/addons/components/gusek-workbench.tsx:156`:
  the same error.

Cause: the pinned R15 modules each contain one `eslint-disable-next-line`
comment for `react-hooks/exhaustive-deps`, but upstream LearnHarness 0.4.1's
ESLint config has no registered `react-hooks` plugin. Installing another plugin
or altering upstream-owned ESLint/package files is unnecessary.

The portable namespace rewriting removes **only those two exact directives**
from the private assembled copies. It does not change their React effects,
dependency arrays, state, MathProg model, score logic or frozen R15 sources.
The frozen pack rejects a pinned R15 source that does not have exactly one
matching directive in either of the two named files. The existing assembly
integrity verifier independently recomputes and validates the rewrite.

This change is a lint compatibility fix, not a React hooks behavioral review.
The single final Fedora qualification must restart in a NEW workspace to test
all remaining gates. The prior lint failure and npm audit report are not
converted into PASS. Never run `npm audit fix --force` during qualification;
35 dependency advisories were reported by npm, requiring a separate impact
and remediation audit after the build gates are known.

No GitHub Actions hosted-runner, production deployment, main/R15 alteration,
merge or GLPK enablement is authorized here.
