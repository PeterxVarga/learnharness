## Falsified assumption

R16.4–R16.5 moved the GUSEK add-on code into `src/tredven/addons/` and generated Next.js App Router entrypoints in `app/` that directly imported it using `@/src/tredven/addons/...`.

The official LearnHarness pinned upstream `amosblomqvist/learnharness@e69e85269c064c6c9c49a8b06ae78c06e79c4a63` has `eslint.config.mjs` rules prohibiting imports **from `src/` into `app/`**, except the two barrel entrypoints `src/core/index.ts` and `src/server/index.ts`. This makes the previously claimed upstream-first source layout incompatible with the actual upstream lint contract, even if TypeScript resolution succeeds. The build/lint failure itself was not run, so this is a **static confirmed contract violation**, not a reproduced npm log.

Source: https://github.com/amosblomqvist/learnharness/blob/e69e85269c064c6c9c49a8b06ae78c06e79c4a63/eslint.config.mjs

## Narrow change

- Move the add-on source namespace from `src/tredven/addons/` to top-level `tredven/addons/`, without changing the relative topology of extracted original R15 files.
- Generated App Router bridge imports now use `@/tredven/addons/...`. The official `@/* -> ./*` tsconfig alias resolves these paths without any upstream tsconfig edits.
- Keep the existing private receipt type `src/tredven/gusek/attempt-receipt-r15.ts` for this compatibility-only chunk, but no generated `app/**` code imports it. This type is referenced solely by the private relocated add-on source.
- Add a fail-closed import-law gate to the generated `app/**` source check: direct imports from arbitrary `@/src/**` paths and relative source imports into `src/**` are refused. Only existing `@/src/core` and `@/src/server` barrels are allowed.
- The one-shot qualification script now accepts only `tredven/addons/`, preventing old, known-incompatible assembled output from being qualified as R16.6. Its technical receipt is labeled `qualify-r16.sh-r16.6`.
- Existing and newly added tests cover normal core and Workbench profiles, optional native API bridge, intentional regression to the forbidden namespace, source tampering, upstream collision handling and the remaining R16.5 compatibility type.

This repair does **not** introduce a runtime plugin manager, change upstream core/import rules, modify the user's GitHub or Fedora sources, or authorize release.
