## One-time use with local exact Git objects

The bundle itself contains only migration tools and overlays, not full repository source. It does not fetch remote content or modify original checkouts.

```bash
BUNDLE="$HOME/Downloads/learnharness-r16-upstream-first-r165"
R15_REPO="$HOME/path/to/existing/learnharness"     # must contain pinned R15 and base objects
UPSTREAM_REPO="$HOME/path/to/upstream"              # must contain e69e852... commit
PACK="$HOME/Downloads/learnharness-r15-portable-pack"
OUT="$HOME/Downloads/learnharness-r165-assembled"

# Source-only, no npm / app launch.
python3 "$BUNDLE/r16.py" freeze-pack --r15 "$R15_REPO" --out "$PACK"
python3 "$BUNDLE/r16.py" verify-pack --path "$PACK"
python3 "$BUNDLE/r16.py" assemble-pack --upstream "$UPSTREAM_REPO" \
  --upstream-ref e69e85269c064c6c9c49a8b06ae78c06e79c4a63 \
  --addon-pack "$PACK" --profile workbench --out "$OUT"
python3 "$BUNDLE/r16.py" verify-assembly --path "$OUT"

# Once, only with owner authorization and an environment that can reach npm.
bash "$BUNDLE/qualify-r16.sh" "$OUT"
python3 "$BUNDLE/r16.py" verify-qualification --path "$OUT"
```

The optional `--native-route` can be selected during assembly, but `qualify-r16.sh` intentionally requires it absent, disables real GLPK execution and rejects native-release claims. Native GLPK/Podman and visual Chromium qualification require separate explicit execution on the Fedora host. The script never alters the existing R15 or upstream checkout.

**Note about reuse:** R16.4 portable packs must be recreated under R16.5, because the `core` profile's frozen adapter overlay now contains the private receipt type. This is a deliberate pack schema contract change, not an automatic mutable upgrade. Older R16.4 working copies remain unchanged.
