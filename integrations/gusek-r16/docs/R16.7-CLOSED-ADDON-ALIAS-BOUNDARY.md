# R16.7 — Close upstream alias leaks in frozen GUSEK add-ons

Date: 2026-10-31. Design: upstream-first, reuse R15, no parallel plugin platform.

## Verified source-level flaw in R16.6

The original `closure()` walked only **relative imports**. A source module could reference
`@/src/core`, `@/src/server`, `@/components/chat`, or another upstream file using a
TypeScript path alias, and the portable pack's dependency closure would still pass.
`rewrite_namespaced_source()` previously rewrote aliases to own R15 modules, but
**silently left non-owned alias imports unchanged**. If the upstream provided such a
module, the assembled program could compile while retaining a hidden coupling to
upstream internals. This is a source-level falsification of full isolation, not an
observed real Next.js crash.

## Bounded repair (no new subsystem)

1. During **freeze-pack / closure**, reject any static alias or JSDoc/dynamic alias
   which is not resolvable to the original R15 **added-only selected source set**.
   This also keeps the closure proof meaningful for `@/` paths.
2. During **assemble-pack**, rewrite static and dynamic `@/` references to owned
   files under `tredven/addons/`. Fail closed on unknown/upstream aliases with
   `ADDON_UPSTREAM_ALIAS_LEAK`.
3. Preserve the **one** existing private R15 compatibility type shim
   `@/src/tredven/gusek/attempt-receipt-r15`, supplied by the frozen overlay. It
   is the sole intentional exception, not an unrestricted upstream import.
4. Continue to permit external **package** imports (`react`, `next/link`, Node
   built-ins), unchanged relative imports within the transplanted add-on, and
   existing `R15` synthesized API route bridges. No Next configuration, ESLint
   import law, or upstream source changes are made.
5. Version the qualification receipt as `qualify-r16.sh-r16.7` to distinguish
   incompatible predecessors.
