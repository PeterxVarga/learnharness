# R16.15 — GUSEK submit/edit race and dependency security disposition

## User-visible defect and narrow source fix
The R16.14 browser user journey succeeded on both subject types, but its test did not overlap editing and a delayed assessment POST. In R16.14's source the `active.current` boolean could remain true after `invalidate()` set `busy=false`, allowing an enabled submit control that silently ignored the user's click.

R16.15 keeps the existing server-only grading route, exact integer proofs, all API contracts, frontend layout, and the R16 portable assembler unchanged. The subject component replaces the boolean active flag with an owned `AbortController`:
- Any edit/reset/new task load increments the request epoch, aborts the previous grading POST and clears ownership before allowing a new submit.
- Each POST has its own `AbortController.signal` and a monotonically increasing epoch ticket.
- The prior POST's `finally` releases only **its own** controller. An older completion cannot release a later POST's ownership or change the later task's `busy`/grade/error.
- The server retains sole grading authority; cancelling the browser fetch does not guarantee cancellation of server-side processing and must not be treated as such.

## Evidence and acceptance boundary
Targeted source contracts are in `tests/test_r1615_submission.py`. A React/Chromium delayed-request regression on a newly assembled R16.15 candidate is required before marking the user-visible race fixed. Do not interpret source-only checks or the R16.14 success (on an earlier build) as proof that R16.15 runs in the browser. Use the existing R16.13 build and HTTP harness; avoid rebuilding parallel infrastructure. Original secure upstream remains pinned at `80f225d1fe16483b8e018b51dbfef4465262156e`.

## Development dependency risk
Owner's R16.14 full npm audit: **23 moderate package entries, zero high/critical**, all chaining to one root `minimatch` advisory GHSA-g3hv-75wg-m249. Ten affected installed `minimatch` trees are all `dev:true`. The production-only audit already returned zero issues, but the full audit **did not pass**. A threat-modelled acceptance may be considered for *isolated internal development* only; this is not risk elimination and not a declaration that developer tools are safe against attacker-controlled glob input. Do not run global `npm audit fix --force`, or blanket override older minimatch majors, without compatibility review.
