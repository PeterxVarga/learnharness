# LearnHarness R16.9 — Task-aware teaching bridge

Date: 2026-10-31. Owner controls every chat submission. Extend the actual R15 Workbench; no parallel tutor, scoring service, database, or core source patch.

## Research → reuse → build → falsify

- Reused R15 server-side 0/1/null grade, R15B three-step diagnoses, and R16.8 human-controlled tutor handoff. Existing R15E **Javítom és újra beadom** path already provides the return to the same task; do not duplicate it.
- Verified upstream 0.4.1 `app/chat/new/page.tsx`: `mode=teach` selects standard teach mode; the new page does not create a chat until the learner sends. Link to `/chat/new?mode=teach` is a normal user-click navigation, **not** a write or background call.
- The R16.8 brief lacked actual exercise parameters, forcing the learner to paste task data separately and limiting the tutor's ability to identify a specific modeling gap. R16.9 adds **only learner-visible exercise facts**, not the model/solution.

## Functionality and guarantees

1. After an R15 grade, the add-on's handoff receives the **same current task** via the single protected GUSEK Exam insertion point (`task={task}`) and verifies task/grade ID, family, optional seed, numerical types and shape.
2. Uses a strictly allowlisted formatter for three public R15 task types: 3x3 transport (supplies/demands/costs/capacities), ten-product fröccs (ingredients, unit prices, resource limits), two-variable tablets (cost/knowledge constraints).
3. If any input does not match, the feature falls back to a generic tutoring handoff and asks the student for the exercise statement. Unknown task fields are never serialized (raw `.mod/.dat`, submitted values, oracle/solution, GLPK token, chat ID, etc.). Numeric task data **is** transmitted if the user manually pastes the copied brief into the teaching chat. No claim that frontend task data itself is cryptographically authenticated; server grading remains authoritative.
4. The user clicks **Brief másolása**, then **Tanítóbeszélgetés megnyitása** (an upstream `mode=teach` link), pastes the brief and shares their own reasoning. The tutoring agent is asked to pose one question at a time and withhold the complete model/optimum. Model behavior cannot be guaranteed by prompt alone.
5. The learner returns to the same GUSEK task, invokes the *existing* repair button and submits the corrected answer to the original server grade endpoint. No new state ledger, auto-send, auto-grade or provider call.
6. The add-on is still frozen once into a portable, checksum-locked package and assembled under `tredven/addons/` on future upstreams. `core` profile unchanged. The optional native GLPK route stays off.
