# R16.13 — Security-pinned upstream integration (NO_SEND / NO_RELEASE)

## Outcome and architectural decision

Use the **existing** R16 `assemble-pack` and `verify-assembly` APIs. There is no new assembler, no mutation of upstream/R15 checkouts, no npm automation, and no merge/deployment. The small `r1613-security-upstream.py` preflight accepts one specifically reviewed, immutable security commit as the upstream **tree** and requires source provenance before an isolated R16 portable assembly.

- Official upstream LearnHarness 0.4.1 base: `e69e85269c064c6c9c49a8b06ae78c06e79c4a63`.
- Security-review tree: `80f225d1fe16483b8e018b51dbfef4465262156e` on `work/learnharness-r16129-security-deps-no-release`.
- GUSEK original R15 source: `9b7f374f4003276e67a96feb070124c244447aec` (unchanged).
- The security tree changes **only** `package.json` and `package-lock.json`; manifest-only direct override of `ansi-to-react -> linkify-it@5.0.2`, 32 updated lockfile versions, and one obsolete nested lockfile entry removed. No independent upstream source modifications.

The source gate rejects wrong HEAD, dirty worktree, missing base ancestry, extra modified files, arbitrary scripts/dependencies, lockfile-root changes, same-version metadata changes, unknown registries, changed install scripts, wrong patched versions, or changed package-entry count. The authoritative published commit and base are **hard-coded**, not user-replaceable CLI flags. This is a hash-pinned contract, not a code-signing or malicious-operator attestation.

After assembly, `verify-assembly` verifies the entire existing R16 source pack and original Next post-build allowances. An additional **independent `git archive` comparison** hashes the *whole pinned security tree* and matches it to `evidence/upstream-files.json`, rather than trusting the assembly's own self-reported inventory alone.

## Owner Fedora invocation (local, isolated)

Assume the new R16.13 GUSEK add-on branch is locally cloned as `$BUNDLE`, and the previously verified R16.12.6 pack exists at `$BASE/candidate/addons-source`.

```bash
set -Eeuo pipefail
umask 077
SEC="80f225d1fe16483b8e018b51dbfef4465262156e"
BASE="$HOME/Downloads/lh-r16126-http-09bXM7Wf"
BUNDLE="$HOME/Downloads/your-new-r1613-clone/integrations/gusek-r16"
DEST="$(mktemp -d "$HOME/Downloads/lh-r1613-XXXXXXXX")"

git clone --quiet --depth 3 --single-branch \
  --branch work/learnharness-r16129-security-deps-no-release \
  https://github.com/PeterxVarga/learnharness.git "$DEST/security-repo"
test "$(git -C "$DEST/security-repo" rev-parse HEAD)" = "$SEC"
(cd "$BUNDLE" && sha256sum -c SHA256SUMS >/dev/null)

python3 "$BUNDLE/r1613-security-upstream.py" assemble \
  --security-repo "$DEST/security-repo" \
  --addon-pack "$BASE/candidate/addons-source" \
  --out "$DEST/candidate"

# Source-only qualification; do not claim the runtime is verified yet.
python3 "$BUNDLE/r1613-security-upstream.py" verify \
  --security-repo "$DEST/security-repo" --candidate "$DEST/candidate"
```

Run `npm ci`, the already-reused R16 Next.js build/HTTP smoke, the targeted browser/PDF checks and `npm audit --omit=dev` **only on this exact assembled candidate**, as appropriate for the final combined approval gate. Verify post-build using `verify --post-build`, which preserves the original explicit Next source integrity allowlist. Do not replace or weaken it. No official R16 qualification, release, GitHub Actions run or owner approval is implied by the source-only gate.
