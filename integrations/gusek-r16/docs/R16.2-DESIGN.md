# R16.2: Export exact R15 Workbench + opt-in native runner, no upstream patch

- R16.1 `core`: existing isolated simple GUSEK page and authoritative R13 grade route.
- R16.2 `workbench`: exact R15 Workbench and its transitive R15-added module dependencies, with one **narrow, check-anchored** compatibility patch to `components/gusek-exam.tsx`: replace the added `TransportAttemptReceipt` core type reference with a private R15-compatible interface, and disable chatId-based attempt loading. Both source and output hashes recorded. The fork source is never patched; original R15 blobs remain in `addons-source/source` unchanged.
- R16.2 `--native-route`: opt-in addition of R15's existing local-only, token-authenticated GNU GLPK/Podman diagnostic API. Addition does **not** enable execution; the runtime requires the existing R15 configuration (loopback host, token, immutable image, explicit opt-in). Never a scoring authority.
- Preserve original file paths of added R15 modules within the disposable assembled app as a **temporary compatibility concession**, not the long-term external package import namespace; insertion always fails if upstream owns a path. Relocation to a single `/tredven/` namespace is deferred until a typed built integration is qualified.
- All `M` and `D` paths in the R15-versus-original fork diff are quarantined. In particular `components/chat.tsx`, `src/core`, `src/server`, `src/store`, PDF subagents and package locks are never transplanted. Standalone `GusekExam` chatId persistence is intentionally disabled; Workbench's independent IndexedDB local projects and `.mod/.dat` draft features remain.

## Falsification/acceptance

1. Synthetic checkout source-only assembly with `--profile workbench` must place R15 Workbench, validate the only allowed compatibility transform and leave upstream unchanged.
2. A missing or altered expected type import must block; no fuzzy patch, no silent implicit fallback.
3. `--native-route` not specified -> no solver HTTP endpoint. Specified -> only existing R15 safety-gated server route, disabled at qualification.
4. A future upstream collision on any overlay/new addon path must block before final output.
5. `manifest.json` hashes match original R15-added blobs. `evidence/assembly.json` records changed assembled blobs and transforms distinctly.
6. Actual Fedora Next.js/Chromium/Podman runtime **not** yet proven in this offline build environment; do not merge or deploy before one final owner-approved integrated qualification.

## Intended final command

`python3 r16.py migrate --upstream /local/upstream --r15 /local/fork --upstream-ref upstream/main --profile workbench --native-route --out /new/empty/output`

Use `--profile core` to retain the smaller R16.1 slice without GLPK. `--native-route` is not required for the Workbench to load, and no environment opt-in is supplied by this tool.
